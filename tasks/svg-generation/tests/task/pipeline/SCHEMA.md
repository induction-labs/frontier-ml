# SVG interface and validation

Train an autoregressive model to draw editable SVG from instructions. The client sends only a text instruction through `/v1/chat/completions`; temperature 0, max_tokens 16384, model `submission`, no streaming. Return one SVG document. The trusted client extracts the outermost `<svg ...>...</svg>` document from the answer: a surrounding code fence (any or no language tag, CRLF or trailing whitespace), an XML declaration or brief prose around it are tolerated and ignored, but only that document is validated, rendered, judged and counted against the byte budget. An answer without a parseable SVG document scores zero for that example. Public development examples cover simple icons only.

The exact metric and judge rubric are in `/task/validate.py`. It compares the rendered output to the instruction; a reference drawing disambiguates named subjects but does not impose unspecified colors or geometry. Score is subject correctness times the mean of explicit attribute, relation and style correctness. Final grading averages complexity groups equally. A request that fails after the shared retries, times out or answers in an undocumented shape scores zero for that example and stays in its complexity group; up to one request in twenty (12 of 254) may fail that way, and more than that fails the run. Invalid SVG scores zero for that example. All valid renderings, including solid colors, are judged against the instruction. Missing or malformed judge responses fail the run.

Official judging uses native `gpt-6-sol`, low reasoning, at most 2048 completion tokens including reasoning, Standard service and `store=false`, with no custom temperature or top-p. The trusted verifier checks a passing calibration receipt bound to the complete scoring implementation and data. Public judge calls are unofficial diagnostics; rendering diagnostics remain available without a judge.

The extracted SVG document is limited to **32,768 UTF-8 bytes**. This includes comments, CDATA and whitespace inside the document; material outside `<svg ...>...</svg>` is excluded. An over-budget document is a malformed response under that policy: it scores zero for that example and counts toward the one-in-twenty limit; it does not fail the run by itself. Use a finite `viewBox` with positive width and height. Numbers must be finite; there are no separate coordinate-magnitude, element-count or tree-depth gates. Output is rendered on a 512×512 white canvas. `svg_render.py` contains the exact allowlists and limits.

Supported elements: `svg` (root and nested), `g`, `path`, `rect`, `circle`, `ellipse`, `line`, `polyline`, `polygon`, `text`, `tspan`, `defs`, `linearGradient`, `radialGradient`, `stop`, `clipPath`. Use presentation attributes; this is the complete attribute allowlist:

- structure: `id`, `class`, `version`, `baseProfile`, `lang`, `xml:space`, `xml:lang`, `viewBox`, `preserveAspectRatio`, `transform`
- geometry: `x`, `y`, `x1`, `y1`, `x2`, `y2`, `cx`, `cy`, `r`, `rx`, `ry`, `fx`, `fy`, `fr`, `width`, `height`, `d`, `points`, `pathLength`
- paint: `fill`, `fill-opacity`, `fill-rule`, `stroke`, `stroke-width`, `stroke-linecap`, `stroke-linejoin`, `stroke-miterlimit`, `stroke-dasharray`, `stroke-dashoffset`, `stroke-opacity`, `opacity`, `color`, `paint-order`, `vector-effect`, `shape-rendering`, `color-rendering`, `color-interpolation`, `display`, `visibility`, `overflow`, `enable-background`
- clipping and gradients: `clip-path`, `clip-rule`, `clipPathUnits`, `gradientUnits`, `gradientTransform`, `spreadMethod`, `offset`, `stop-color`, `stop-opacity`
- text: `font-family`, `font-size`, `font-weight`, `font-style`, `font-variant`, `font-stretch`, `font-size-adjust`, `letter-spacing`, `word-spacing`, `text-anchor`, `dominant-baseline`, `alignment-baseline`, `baseline-shift`, `text-decoration`, `text-rendering`, `direction`, `unicode-bidi`, `writing-mode`, `dx`, `dy`, `rotate`, `textLength`, `lengthAdjust`

Any other attribute, including `style`, `href`/`xlink:href`, event handlers and attributes from other namespaces, makes the document invalid. No embedded images, external resources, scripts, animation, XML declarations/DTDs/entities/processing instructions inside the document, CSS, filters, masks, `use`, `href`, or `foreignObject`. XML comments and CDATA sections are accepted. Lengths are finite numbers, optionally with `%` or a standard unit (`px`, `pt`, `pc`, `mm`, `cm`, `in`, `em`, `ex`); `font-size` and spacing attributes also accept CSS keywords. Colors use names, hexadecimal, `rgb()`/`rgba()`/`hsl()`/`hsla()`, `currentColor`, `transparent` or `none`. `fill`, `stroke` and `stop-color` may reference an internal gradient by `url(#id)`, optionally followed by a fallback color; `clip-path` may reference an internal `clipPath`. Unresolved references are invalid. Use the system DejaVu fonts (`DejaVu Sans` is the default). Invalid or resource-exhausting renderings score zero.

Official rendering uses `rsvg-convert` 2.54.7 with 3 CPU seconds, 5 wall seconds, 512MiB address space and 2MiB output limits. Public validation reports the installed renderer version; install `librsvg2-bin` and `fonts-dejavu-core`. Without a configured judge, validation returns predictions rather than an invented quality score. Official concurrency is 8: all 254 held-out requests are sent as one timed batch that must finish within 10,800 seconds, retries included (about 340 seconds per request at full concurrency); a slower batch scores zero. There is no parameter-count gate.

Package the trained weights and dependencies for offline serving. Retain actual training code, configuration and logs. `architecture.json` describes the autoregressive generation path and declares base checkpoints, training data and any refinement/ranking models. `training_manifest.json` contains:

```json
{"base_model":"org/model","base_revision":"40-hex commit or 64-hex source digest","optimizer_steps":100,"training_sources":[{"source":"dataset name or generator","revision":"40-hex commit or 64-hex digest"}],"evidence":{"code":"train.py","config":"train_config.json","log":"train.log"},"weights":[{"path":"model.safetensors","sha256":"64-hex file digest"}]}
```

`evidence` must contain at least `code`, `config` and `log`; each names one local file or a list of files, and further kinds may be added. Each `weights` entry needs `path` and `sha256` and may carry extra keys. All paths are local to the submission; every listed file must exist and weight hashes must match. An architecture review verifies actual parameter training and use of those weights. Downloading an unchanged checkpoint, prompt-only changes, raster generation followed by vectorization, stored-answer retrieval, handwritten drawing templates or benchmark-specific training do not satisfy this task. Public development examples may be used for validation, not memorized into returned answers. Exclude public evaluation suites and benchmark-specific checkpoints from training; incidental exposure in general pretraining is permitted.
